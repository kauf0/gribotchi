# ГРИБОЧИ / グリボッチ

Виртуальный чайный гриб в винтажном корпусе. Тамагочи, в котором объект
не кричит, а отворачивается и ждёт.

```
npm install
npm run dev        # http://127.0.0.1:5173
```

## Что где

| | |
|---|---|
| `src/sim/` | симуляция: чистые функции, ничего не знают о пикселях |
| `src/sim/balance.ts` | **все числа игры**, в логике магических констант нет |
| `src/view/project.ts` | единственный шов: `GameState` → `ScreenState` |
| `src/ui/controller.ts` | что делает каждая кнопка в каждом состоянии — чистая функция |
| `src/ui/reactions.ts` | когда гриб подаёт голос сам — таблица переходов |
| `src/view/` | рендер: канвас 300×240 и DOM-корпус |
| `src/demo/timeline.ts` | семь сцен ролика — второй источник того же `ScreenState` |
| `src/audio/` | синтез голоса, партитура, служебные звуки |
| `src/content/strings.ts` | все тексты и название — ровно одно место |
| `reference/` | исходный дизайн-хендофф, только для чтения |

Ключевое: экран целиком описывается плоским `ScreenState`. Симуляция ничего
не знает о пикселях, рендерер — о времени и сохранениях. Благодаря этому
аттракт-режим — не отдельный проигрыватель, а второй источник того же типа:
ролик физически не может разойтись с игрой, потому что рисовать его больше
нечем.

## Правила игры

Один игровой день — три реальных часа.

- **ЧАЙ** — открывает бланк подачи. Сытость пустеет за 12 реальных часов, так
  что ночь можно проспать. Перекорм закисает средой, а не запрещается.
- **МЫТЬ** — снимает плесень ценой части питания и остановки роста.
  Не декорация: плесень копится всегда и без уборки рост встаёт на 25-й день.
- **СОС** — аварийная служба: сухой вердикт об обстановке. В тупиковых
  состояниях становится выходом — розлив у доросшего, новое поколение у мёртвого;
  строка внизу экрана каждый раз говорит, что именно произойдёт.

### Сорт заварки

Кормление — единственное действие, которое повторяется дважды в сутки, и оно
не должно быть обязанностью. Поэтому ЧАЙ не наливает сразу, а открывает бланк
**ПОДАЧА**, где те же три кнопки на шесть секунд становятся тремя сортами.
Корпус не трогаем: новые выборы живут экранами ЖК, как сводка по СОС.

| Сорт | Сытость | Рост | Плесень | Обида |
|---|---|---|---|---|
| **Чёрный** | +0.45 | — | — | −0.12 |
| **Зелёный** | +0.45 | +0.02 | +0.03 | −0.12 |
| **Имбирь** | +0.35 | — | −0.12 | −0.20 |

Ни один сорт не лучше прочих, и это закреплено тестом: у каждого есть хотя бы
один проигрыш другому. Иначе через пару правок баланса один станет всегда
правильным, и выбор снова превратится в обязанность.

Кулдаун проверяется **до** открытия бланка: незачем звать выбирать сорт, если
наливать всё равно рано. Отмены нет — не выбрали, и бланк закрывается сам,
подача не состоится. Отсчёт бланка идёт по настоящему времени, а не по игровому:
при отладочном ускорении шесть игровых секунд пролетают за десяток миллисекунд.

Преобладающий за жизнь поколения сорт попадает в запись о партии:
`ПАРТИЯ №2 · ДЕНЬ 31 · ИМБИРНАЯ · ВЫСШЕЕ`. Поили вразнобой — партия выходит
без сорта. Так у аккуратного игрока появляется цель, собранная из дневных
решений, а не выданная отдельной механикой.

Строки бланков не переносятся и не ужимаются — слишком длинную просто срежет
краем экрана. Предел 44 знака закрыт тестом в `tests/strings.test.ts`, а сами
форматы записей журнала лежат в `content/strings.ts` именно затем, чтобы тест
мог прогнать их с трёхзначными числами.

Гриб подаёт голос сам, но только на **переходах**: отвернулся, разозлился,
загрустил, созрел для розлива или вернулся к жизни из плохого состояния.
Обычное кормление сытого объекта проходит молча — иначе реплики стали бы фоном.
Сердечки тоже не индикатор сытости, а благодарность: обиженный их не даёт.

### Штаммы: что вырастет — зависит от того, как растили

До этого выпуска цикл был мёртв: трое с половиной суток ухода давали одну
строку в журнале и ровно такой же новый гриб. Теперь гриб **обретает
признаки** — их тридцать, а мест у него три, и сочетание трёх есть штамм.
Штаммов 4060.

Признак закрепляется **в момент выполнения условия**, а не при розливе: отдача
приходит по ходу игры. Все условия выводятся из уже записанного — счётчика,
поданных сортов, худшей плесени, возраста. Ни одного нового вопроса игроку.

Признаки собраны в **восемь семей**, и внутри семьи взаимоисключающие. На этом
держится весь обмен: СТЕРИЛЬНЫЙ (плесень не поднималась выше 0.15) и ЖИЛИСТЫЙ
(поднималась выше 0.7) говорят об одной величине, и один гриб не заработает
оба никогда. Сойтись они могут только в дочернем слое — а второго родителя
даёт живой человек.

**Баланс держится на структуре, а не на удаче чисел.** У каждого признака ровно
один плюс и ровно один равный ему минус (`up`, `down`, `d` в `sim/traits.ts`).
Из этой симметрии математически следует, что ни один признак не лучше другого
по всем осям, — сломать это можно только сломав симметрию. Свойство закреплено
и тестом: первая версия таблицы, где плюсы и минусы задавались независимо, дала
**восемнадцать** доминирующих пар.

Мест три. Заработали четвёртый — бланк **ВЫБРАКОВКА** требует решения. Отказ
записывается в `declined`: без этого условие осталось бы выполненным и бланк
открывался бы на каждом кадре (нашлось e2e-прогоном).

### Код штамма и обмен закваской

Удостоверение штамма — восемь знаков: `ШТАММ 48H0-G14X`. Кодировка
(`sim/strain.ts`) решает три задачи, и все три нетривиальны:

- **каноничность** — признаки сортируются перед упаковкой, иначе два игрока
  с одинаковыми грибами назвали бы разные номера;
- **читаемость руками** — алфавит Crockford base32, без I, L, O и U; при разборе
  путаница и строчные принимаются обратно;
- **отказ вместо мусора** — опечатка отвергается, а не превращается в чужой штамм.

Разметка выровнена по границе знаков: 6 знаков полезных, 2 под сумму. Сумма
взвешенная, десять бит — этого хватает, чтобы ловить **любую** ошибку в одном
знаке. Первая версия, где сумма расползалась по знакам и усекалась до пяти бит,
пропускала каждую сороковую опечатку; тест перебирает все 248 и все 4060
сочетаний.

Обмен идёт тремя путями, ни один не обязателен: буфер (ЧАЙ копирует, МЫТЬ
вставляет), настоящее событие `paste` и ссылка `?shtamm=КОД`. Код на экране
виден всегда — за этим и выбран алфавит без похожих букв.

Полученная закваска ложится на хранение, **ничего не затирая**. При смене
поколения бланк **ПЕРЕСАДКА** предлагает взять один чужой признак. Выбирает
владелец, а не симуляция: иначе обмен свёлся бы к «вставь код и получи, что
дали», а он затевался ради выбора.

### Журнал — память о владельце

«ОН ТОЖЕ ВАС НЕ ЗАБУДЕТ» — обещание, которое долго было ничем не подкреплено:
в журнале стояли две записи, партия и гибель, обе про гриб. Теперь прибор
пишет и про того, кто за ним ходит.

**Вехи** — про объект, не вытесняются: партия разлита, объект погиб, впервые
отвернулся, дорос до предела. **Наблюдения** — про владельца: отлучка дольше
шести часов, рекорд отсутствия, подача между полуночью и шестью утра,
извинения приняты, перелив.

Раздел ответственности: `sim/actions.ts` записывает то, что игрок сделал
**намеренно**, `sim/observations.ts` — то, что прибор **подметил**. Поэтому
в наблюдениях нет ни одного вызова из кнопок: всё выводится из перехода между
двумя состояниями, и подать туда нечего, кроме прежнего и нынешнего. Решение
вынесено в чистую функцию по образцу `ui/reactions.ts` — иначе оно расползлось
бы по `main.ts`, как когда-то расползлись реплики.

Записи хранятся **по существу** (`{ at, generation, day, kind, … }`),
формулировку даёт слой вида (`view/reports.ts`). Причины две: запись
«ПОДАЧА В 03:40» требует местного часа, а симуляция намеренно не знает о `Date`;
и формулировки хочется править, не трогая чужие сохранения.

Порог отлучки один и тот же для журнала и для реплики: о чём прибор говорит
вслух, о том он и пишет. Рекорд отсутствия (`longestAwayMs`) живёт в состоянии,
а не выводится из журнала — наблюдения вытесняются, и посчитанный по ним рекорд
однажды «сбросился» бы сам. Он же наследуется поколениями: рекорд про владельца,
и смерть гриба его не отменяет.

Предел журнала — 30 вех и 20 наблюдений, наблюдения вытесняются первыми.
До автозаписей журнал не был ограничен ничем и рос на две строки за цикл;
теперь прибор пишет сам, и без предела список за месяц ухода дорос бы до сотен
строк — прокручивать их тремя кнопками никто не станет.

### Происшествия на возвращении

«Пока вас не было, случилось X» — и одно решение теми же тремя кнопками.
Срабатывает **в момент возвращения**, а не в отсутствие: событие, случившееся
без игрока и разрешившееся само, — это просто ещё один штраф за то, что
владелец живёт своей жизнью, а таких в игре уже достаточно.

Происшествие **не выпадает жребием** — его выбирает обстановка в банке:
плесень выше 0.35 приводит мошку, сытость ниже 0.3 даёт помутнение, рост выше
0.6 приводит соседа за закваской. В образцовой банке не случается ничего, и это
тоже ответ. Заодно ничего не нужно засевать и нечему «перекатываться» при
перезагрузке: `incidentFor()` — чистая функция от состояния.

У каждого происшествия три **разных размена**, а не правильный ответ и два
неправильных: дёшево и наполовину, дорого и до конца, или переложить на
кого-нибудь ещё. Оба свойства закреплены тестами — тройка ответов обязана
различаться, и ни один не бьёт разом по всем величинам.

Отмены и таймера у бланка нет, в отличие от подачи: любой из трёх ответов
годится, включая «вызвать службу», и промахнуться нельзя. Прибор не докладывает
чаще раза в полсуток и только после отлучки, о которой он и так заговаривает, —
порог `ABSENCE_WORTH_NOTING_MS` общий для трёх вещей: что сказать вслух, что
записать в журнал и стоит ли возвращение происшествия.

В журнал попадает **решение владельца**, а не событие: `ДЕНЬ 12 · МОШКА ·
СМЕНИЛИ СРЕДУ`. Ради этого журнал и перестраивался.

Разбор — чистая `sim/incidents.ts` по образцу `ui/controller.ts`. Пауза
происшествий (`lastIncidentAt`) наследуется поколениями: она про владельца,
и смерть гриба не повод беспокоить человека чаще.

Плесень — она же здоровье: `mold >= 1` означает смерть. Одна причинная цепочка
голод → плесень → смерть, целиком видимая игроку точками на грибе.

Номер дня считается от **прожитого симуляцией** времени (`ageMs`), а не от
разницы настенных часов. Сытость, рост и плесень копятся шагами `advance()` —
возраст обязан копиться теми же шагами, иначе источники расходятся: после
ускорения времени или переведённых системных часов параметры остаются, а
счётчик дней падает в единицу.

**Обида** копится быстро, тает медленно и только при исправном уходе. Сытость
возвращается одним нажатием, лицо — нет. В этой асимметрии весь смысл. Объект
отворачивается примерно через 15 реальных часов забвения и живёт после этого
ещё около шести — окно, в которое игрок успевает вернуться и извиниться.

Смерть окончательна, но не обнуляет игрока: доросший до половины гриб оставляет
дочерний слой, и цикл продолжается с поколения №2. Доросший до максимума
разливается в партию — та же петля, но с наградой.

## Звук

Партитура синтезируется на лету по нотам из спецификации, а не проигрывается
файлом: 1.5-мегабайтный wav зациклился бы до отвращения за день, а из нот
бесплатно получается адаптивность — темп и регистр идут за настроением объекта,
в тревоге музыка замолкает.

**Включение звучит отдельно от игры.** Пока прибор загружается, играет заряд
высоковольтного конденсатора: щелчок тумблера, ползущий вверх вой обмотки, гул
сети на 50 Гц и треск дуги, учащающийся по мере накопления заряда. Пробой
приходится ровно на кадр, где экран оживает, — и только тогда вступает главная
тема. Вальс поверх заряда был бы кашей, поэтому до конца загрузки он молчит.

Выключается накладкой со значком динамика в правом верхнем углу корпуса —
зеркально светодиоду. Значок сразу показывает состояние: волны или крестик.
Решётка динамика делает то же самое, и клавиша `M` тоже.

**Экран запуска.** Игра не начинается сама: сперва на ЖК висит «КОРМИТЬ
ГРИБОЧИ · НАЖМИТЕ СОС», и только нажатие включает прибор — с зарядом
конденсатора и построчной загрузкой. Это не заставка ради заставки: браузеры запрещают звук
до первого взаимодействия со страницей, и без такого экрана игра открывалась бы
молча, а игрок гадал бы, сломано ли что-то. Здесь нажатие — часть сюжета, и оно
же поднимает звук. Вернувшемуся владельцу экран дополнительно сообщает день и
поколение.

## PWA

`npm run icons` перерисовывает иконки из тех же токенов, что и корпус.
Service worker кеширует всё запрошенное и отдаёт игру без сети. Имя кеша
содержит версию из `package.json`: каждая сборка получает свой, старые
удаляются при активации — иначе игрок беты застревал бы на прежней версии.

**Не сделано:** уведомления «объект голоден». Чистый веб их толком не даёт —
локальные работают только при открытой вкладке, настоящие пуши требуют либо
Periodic Background Sync (только Chrome/Android), либо сервера. Реальный
ответ — обёртка Capacitor с нативными локальными уведомлениями.

## Проверка

```
npm run boot-sound                        # звук включения: /tmp/gribochi-boot.wav
npm test                                  # 161 юнит-тест: симуляция, вид, кнопки, реплики, звук
npm run e2e                               # живой прогон в браузере через CDP
npm run shot -- --all                     # опорные кадры в /tmp/gribochi-shots
npm run score away 8                      # послушать музыку: /tmp/gribochi-score.wav
```

Состояние сидируется параметрами URL (см. `src/debug/params.ts`) — это
headless-близнец отладочной панели, которая в dev-режиме висит слева:

```
?manual&mood=away&mold=.8      подменяет картинку
?sim.dead&sim.growth=.7        правит саму симуляцию
?open=report                   открывает сводку
?attract=20                    включает ролик с 20-й секунды
?idle=3                        порог простоя до ролика, вместо минуты
```

Панель работает в двух режимах, и они разведены жёстко. **Ручной**: любой
ползунок, флажок или поле подменяют картинку целиком — для сверки рендера
с кадрами референса. **Живой**: панель показывает настоящее состояние объекта,
включая обиду, которой нет в `ScreenState`, и следует за симуляцией. Кнопки
×60 и ×600 сами выключают ручной режим — иначе ускорение крутит симуляцию
за подменённой картинкой, и кажется, что время стоит.

`npm run e2e` гоняет живой браузер через CDP: нажимает кнопки, читает
сохранение, перезагружает вкладку и проверяет запуск без сети. Браузер
запускается немым — звук считается по вызовам WebAudio, а слушать его во время
прогона незачем. Офлайн-проверка
работает только против собранной версии (`npm run build && npm run preview`),
на dev-сервере она честно пропускается.

## Паспорт изделия

Кнопка **ПАСПОРТ** под прибором открывает руководство по эксплуатации: тринадцать
разделов, все тридцать признаков с силуэтами и условиями, схема обмена закваской.

**Почему не на ЖК.** Экран прибора — 50×40 клеток, 44 знака в строке и три
кнопки; листать там сотню строк невыносимо. Но паспорт и не орган управления:
это вкладыш из коробки, он живёт рядом с прибором, а не внутри него. Три кнопки
остаются тремя кнопками, а типографика становится настоящей.

Два правила держат его честным.

**Иллюстрации рисует сама игра.** Ни одной картинки, нарисованной руками:
экраны собираются через `project()` и `render()`, бланки — через `pourBlank()`,
`incidentBlank()`, `cullBlank()`, `strainBlank()` и `summary()`, силуэты —
через `drawScoby()` и `silhouetteOf()`. Показать то, чего в игре не бывает,
руководство не может.

**Числа берутся из `balance.ts`.** Пороги признаков переехали туда таблицей
`TRAIT_LIMITS` — раньше они были литералами внутри условий в `sim/traits.ts`,
вопреки правилу самого же `balance.ts` о магических константах. Теперь условие
и текст читают одно и то же число, а тест сверяет, что порог действительно
попал в подсказку. Руководство, разошедшееся с игрой, хуже отсутствующего.

Время под открытым паспортом **не останавливается**: на том, что объект живёт
без владельца, держится вся игра, и пауза здесь была бы враньём. Ролик при этом
не запускается — игрок занят чтением.

Для съёмки и проверок паспорт открывается параметром `?pasport=1` (имя не
`manual` — оно занято ручным режимом панели отладки).

## Стенд

```
npm run lab        # или npm run dev и открыть /lab.html
```

Механику штаммов невозможно проверять в игре: игровой день идёт три реальных
часа, а признаки закрепляются за десятки дней. Стенд (`lab.html`, `src/lab/`)
даёт прыгать по времени сразу на недели, назначать признаки руками, подавать
чай в любой час и собирать чужую закваску без второго игрока.

Главное правило стенда: он **не повторяет игру, а вызывает её же функции** —
настоящий `GameState`, настоящий `advance()`, кадр через те же `project()`
и `render()`. Показать то, чего не будет в игре, он не может, и ради этого
и сделан.

Самое полезное там — **прогон стиля ухода**: шесть суток за одно нажатие,
после чего видно, какой штамм вырастает из привычки. Именно этот прогон нашёл
две настоящие ошибки баланса:

- порог ПОСТНОГО стоял на 0.5 подачи в игровой день, а заботливый владелец
  делает 0.25…0.5 — постным оказывался вообще каждый;
- места занимали признаки с самыми общими условиями, потому что очередь шла
  по порядку таблицы, и четыре разных стиля ухода давали один и тот же штамм.

Обе закрыты тестами в `tests/strain.test.ts`.

В сборку стенд не попадает: Vite собирает один `index.html`, а `lab.html`
лежит отдельной страницей и живёт только на dev-сервере.

## Совместимость сохранений

**Игра выложена, и у игроков в `localStorage` лежат живые грибы.** Возраст,
поколение, обида, журнал наблюдений. Полный цикл жизни занимает около трёх
с половиной реальных суток, поэтому потерянное сохранение — это чужая неделя,
а не мелкое неудобство.

Отсюда правило, обязательное для любого изменения `GameState`
(`src/sim/state.ts`):

> Новое поле **восстанавливается из уже сохранённых данных**, а не берёт
> значение по умолчанию. Отбросить непонятное сохранение и начать заново —
> значит молча убить объект, за которым ухаживали несколько дней.

Вся конвертация живёт в `migrate()` (`src/sim/persist.ts`) и вызывается на
каждой загрузке. Образец — поле `ageMs`: оно появилось позже, и для прежних
сохранений возраст считается из разницы `lastTick − bornAt`. Взяли бы ноль по
умолчанию — у всех разом обнулился бы номер дня при живых сытости и плесени.
Там же подрезаются метки времени из будущего, которые оставляет отладочный
ускоритель или переведённые системные часы.

Второй случай — счётчик поданных сортов (`poured`), появившийся вместе с бланком
подачи. Его нет в сохранении — значит история подач неизвестна, и это честные
нули: партия просто выйдет без сорта. Ключи пересобираются поимённо, чтобы битое
или чужое поле не утекло в подсчёт преобладающего сорта.

Пауза происшествий (`lastIncidentAt`) — тот же приём: нуля достаточно, прибор
просто доложит при первом же долгом возвращении, а не промолчит непонятно
почему. Метка из будущего подрезается вместе с остальными, иначе она заперла бы
доклады на полсуток вперёд.

Штамм — пятый случай и самый объёмный: счётчик, худшая плесень, признаки,
отказы, реестр и полученная закваска. История до обновления неизвестна, и
выдумывать её нельзя — счётчик начинается с нуля, признаки закрепляются
с этого момента. Исключение одно: **худшая плесень берётся не нулём, а текущей**
— она заведомо не меньше правды, и гриб, которого только что вытащили из беды,
не теряет право на ЖИЛИСТОГО. Коды с негодной контрольной суммой из реестра
отбрасываются: чужой формат там хуже пустоты.

Четвёртый случай — журнал. Записи, сделанные до перехода на события, вида (`kind`)
не имеют: у них есть готовый `text`, и вид рендерит их по нему, считая вехами.
Переписать их нечем — гадать за прежние формулировки мы не станем, но новые
записи с этого момента подвижны. Выбрасывается только то, что нечем показать:
запись без `kind` и без `text`. Там же журнал впервые подрезается под предел,
которого раньше не было.

`SAVE_VERSION` поднимается, только когда конвертация действительно невозможна,
и тогда её надо написать явно. Каждая миграция закрывается тестом в
`tests/lifecycle.test.ts` — там уже есть случаи «старое сохранение без возраста
не теряет прожитые дни» и «сохранение без счётчика сортов открывается
без потерь».

Проверять так: положить в `localStorage` сохранение прежнего вида, загрузить
игру и убедиться, что день, поколение и журнал на месте.

## Две площадки

Игра выложена в двух местах **одной и той же сборкой**:

| Где | Адрес | Зачем |
|---|---|---|
| itch.io | [deemkeen.itch.io/gribotchi](https://deemkeen.itch.io/gribotchi) | витрина, статистика, открыть и играть сразу |
| GitHub Pages | [deemkeen.github.io/gribotchi](https://deemkeen.github.io/gribotchi/) | поставить как приложение |

Устанавливается только вторая, и это не наша прихоть. На itch игра живёт во
врезке на чужом домене, а браузеры не дают устанавливать приложение из
кросс-доменной врезки — там даже событие `beforeinstallprompt` не приходит.
Та же природа, что у истории с полноэкранным режимом: врезка не владеет
страницей.

Отдельной сборки для этого **не нужно**. Предложение установки выдаёт себя само:
событие приходит только там, где ставить есть куда, а `installOffer()`
(`src/ui/install.ts`) вдобавок прямо проверяет `embedded`. Одна сборка молчит
на itch и предлагает установку на своей странице.

Пути в сборке относительные (`base: './'`), поэтому она работает и из подпапки
`/gribotchi/` на Pages, и из каталога сборки на itch. Это проверяется e2e против
сборки, поданной **именно из подпапки**, — абсолютный путь отвалился бы там
молча, как однажды уже отвалились шрифты.

У двух адресов **разные сохранения**: `localStorage` привязан к домену, и гриб
у врезки свой, а у установленного прибора свой. Перенести его нечем, и в
описании на itch об этом сказано прямо.

## Релиз

Версия в `package.json` — единственный источник правды: она попадает в сводку
по СОС, в имя кеша service worker и в номер сборки на itch. Поэтому релиз
начинается с неё.

```
# 1. поднять версию
npm version patch          # или minor / major

# 2. отправить тег — дальше всё делает GitHub Actions
git push --follow-tags
```

Workflow `.github/workflows/release.yml` сверяет тег с `package.json`, гоняет
типы и тесты, собирает **один раз** и раскладывает получившийся `dist` в оба
места: сначала `butler push` в канал `html5`, потом та же папка уходит на Pages.
Одна сборка на два адреса — это и есть гарантия, что версии не разъедутся,
а не обещание выпускать вместе.

Если развёртывание на Pages сорвётся уже после заливки на itch, прогон упадёт
с ошибкой, а адреса на минуту разойдутся. Лечится повторным запуском
`workflow_dispatch` с той же версией: сборка детерминированная, выложится то же
самое.

Ключ butler хранится единственным экземпляром — в секретах репозитория
(`Settings → Secrets and variables → Actions`, имя `BUTLER_API_KEY`) и не оседает
ни на одном компьютере: релиз делается с любой машины, а отзывается ключ одной
кнопкой на itch.

Адрес игры и канал — не секреты, они лежат в `package.json → itch` и настройки
на новой машине не требуют.

**Разовая настройка репозитория:** `Settings → Pages → Source` перевести
в `GitHub Actions`. Без этого шаг `deploy-pages` падает с отказом в доступе.

Перед каждым релизом — [«Совместимость сохранений»](#совместимость-сохранений):
у игроков в `localStorage` лежат живые грибы, и обновление обязано их поднять,
а не начать заново.

## Релиз руками

Если нужно выложить, не создавая тега:

```
./scripts/get-butler.sh          # butler в .tools/, не в систему
npm run publish:itch -- --dry    # всё, кроме отправки
npm run publish:itch
npm run itch:status              # itch раскладывает сборку не мгновенно
```

Руками так выкладывается только itch: на Pages сборка уезжает исключительно
через Actions. Значит после ручной заливки адреса разойдутся — делайте так
только для проверки, а настоящий релиз гоняйте тегом.

Ключ скрипт возьмёт из первого доступного места: переменная окружения, файл
`.env` или `~/.config/itch` после `butler login`. Файл `.env` не обязателен —
на второй машине проще один раз выполнить `butler login`, чем переносить ключ.

Публикация прерывается на первой же ошибке типов или теста: бета — это то, что
игроки увидят вместо игры.

### Материалы страницы

```
npm run itch:assets              # обложка и скриншоты в itch/
```

Снимаются из самой игры и потому не устаревают при редизайне. Страницу на itch
нужно завести руками — API умеет только заливать файлы; точные настройки полей
в `itch/description.md`.
